Groupify — Forge Report

Idea pressure-tested via persona interrogation · 2026-08-14

Outcome: HARDENED

Direction is specific enough to hand to an agent. Distilled contract: forged-idea.md.

Locked decisions

  • LOCK Wedge: BYOD facilitated events — live grid board + one-tap join/leave + admin override is the product.
  • LOCK Night-one scope: session → join by code/QR (+PIN) → pool → grid → create/join/leave → admin move/dissolve/freeze/CSV → offline banner.
  • LOCK No accounts. Display name + per-device token. Fingerprinting deferred (weak by design anyway).
  • LOCK Stack: Laravel 12 + Inertia + React, Reverb (over Pusher), shadcn/ui + lucide, SQLite, Docker dev, Dokploy at groupify.dxtechph.online.
  • LOCK First real user: classmates; demo-grade but must actually work.

Rejected

  • REJECT Chat tiers on night one — biggest scope item; formation is the product.
  • REJECT Postgres + Redis — SQLite suffices at this scale; Postgres is the later scale-out.
  • REJECT Pusher — free tier caps ~100 concurrent connections; Reverb is free, self-hosted, no caps.
  • REJECT "Blue ocean" positioning — feature-count marketing, not a moat. Live-formation loop is the moat.

Weak points that survived scrutiny

  • WEAK Seat-binding ("1 device = 1 seat") is unenforceable on the open web — treat as convenience, not security.
  • WEAK Home-server reliability — mitigated by explicit "server offline" UX, but uptime remains the biggest product risk.
  • WEAK Offline mode ("scan QR, keep working without the server") is the banger quirk but needs its own design pass — PWA shell + sync queue + local/mesh host mode are three different architectures.
